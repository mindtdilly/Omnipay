This guide walks you through the fastest path to a working ProcureNet integration. You'll obtain your API key, start a scored orchestration session, connect to the session's real-time stream, and fire your first state transition — all with TypeScript examples you can run directly against the API. By the end, you'll have a live session flowing through ProcureNet's v7 orchestration pipeline.

<Steps>

  <Step title="Obtain your API key">
    ProcureNet uses separate credentials for different parts of the API. For session orchestration you need a **JWT token** (covered in [Authentication](/authentication)), but to call wallet and payment endpoints you'll need a **mod key**.

    Request your API key from the ProcureNet dashboard or your account team. Once issued, you'll use it as the `x-perplexity-mod-key` header on all wallet and payment requests.

    Store your key in an environment variable and never hard-code it in client-side code:

    ```typescript
    // .env
    PROCURENET_MOD_KEY=your_mod_key_here
    PROCURENET_JWT=your_jwt_token_here
    PROCURENET_BASE_URL=https://api.procurenet.io
    ```

    <Warning>
      Never expose your `x-perplexity-mod-key` or JWT in browser-side JavaScript or public repositories. These credentials carry full API access for their respective scopes.
    </Warning>
  </Step>

  <Step title="Start an orchestration session">
    Call `POST /api/v7/orchestrate` to create a session. Pass identity hints for the buyer — the more signals you provide, the higher the Wallet Confidence Score (WCS) and the richer the session capabilities you'll unlock.

    The `hints` object accepts any combination of `customerId`, `email`, `phone`, and `deviceId`. Each contributes to the WCS score:
    - `customerId` — 100 points
    - `email` — 40 points
    - `phone` — 40 points
    - `deviceId` — 20 points (max total: 200)

    ```typescript
    const response = await fetch(
      `${process.env.PROCURENET_BASE_URL}/api/v7/orchestrate`,
      {
        method: "POST",
        headers: {
          "Content-Type": "application/json",
        },
        body: JSON.stringify({
          amount: 1250.00,
          currency: "USD",
          hints: {
            customerId: "cust_01HXYZ9ABC",
            email: "buyer@example.com",
            phone: "+14155552671",
            deviceId: "dev_fingerprint_abc123",
          },
        }),
      }
    );

    const session = await response.json();
    console.log(session);
    ```

    A successful response returns the session identifier, the calculated WCS score, the resolved mode, and the transport type to use for your real-time connection:

    ```json
    {
      "session_id": "sess_01JKAB3MXPQ7RVTZWN5",
      "wcs_score": 200,
      "mode": "resolved",
      "transport": "sse"
    }
    ```

    Use the `mode` and `transport` fields together to decide how to connect in the next step.

    <Tip>
      A `wcs_score` of 200 means all four identity hints were present and valid. A score ≥ 100 puts the session in `resolved` mode and unlocks prefill data retrieval via `GET /api/v7/sessions/{id}/prefill`.
    </Tip>
  </Step>

  <Step title="Connect to the session stream">
    ProcureNet pushes real-time session events over either SSE or WebSocket depending on the `transport` value in your orchestration response. Open the appropriate connection immediately after starting the session.

    <Tabs>
      <Tab title="SSE (resolved sessions)">
        Use SSE when `transport` is `"sse"` — this applies to all sessions with a WCS score ≥ 100.

        ```typescript
        // Connect to SSE stream for resolved sessions
        const sessionId = session.session_id;
        const streamUrl = `${process.env.PROCURENET_BASE_URL}/api/v7/sessions/${sessionId}/stream`;

        const eventSource = new EventSource(streamUrl, {
          // Pass auth via query param or use a server-side proxy
          // that adds the Authorization header
          withCredentials: true,
        });

        eventSource.onmessage = (event) => {
          const data = JSON.parse(event.data);
          console.log("Session event:", data);
        };

        eventSource.onerror = (error) => {
          console.error("SSE connection error:", error);
          eventSource.close();
        };
        ```
      </Tab>
      <Tab title="WebSocket (partial / anonymous sessions)">
        Use WebSocket when `transport` is `"websocket"` — this applies to sessions with a WCS score below 100.

        ```typescript
        // Connect to WebSocket stream for partial or anonymous sessions
        const sessionId = session.session_id;
        const wsUrl = `wss://api.procurenet.io/api/v7/sessions/${sessionId}/ws`;

        const ws = new WebSocket(wsUrl);

        ws.onopen = () => {
          // Authenticate the WebSocket connection on open
          ws.send(
            JSON.stringify({
              type: "auth",
              token: process.env.PROCURENET_JWT,
            })
          );
        };

        ws.onmessage = (event) => {
          const data = JSON.parse(event.data);
          console.log("Session event:", data);
        };

        ws.onerror = (error) => {
          console.error("WebSocket error:", error);
        };
        ```
      </Tab>
    </Tabs>

    <Info>
      Keep your stream connection open for the lifetime of the session. ProcureNet emits state transition events, escrow status updates, and procurement intelligence results over this channel in real time.
    </Info>
  </Step>

  <Step title="Advance the session state">
    Sessions move through a state machine. Call `POST /api/v7/sessions/{id}/transition` with the target state to advance the session. ProcureNet validates the transition against the current state and rejects illegal moves with a deterministic error code.

    ```typescript
    const sessionId = session.session_id;

    const transitionResponse = await fetch(
      `${process.env.PROCURENET_BASE_URL}/api/v7/sessions/${sessionId}/transition`,
      {
        method: "POST",
        headers: {
          "Content-Type": "application/json",
          Authorization: `Bearer ${process.env.PROCURENET_JWT}`,
        },
        body: JSON.stringify({
          target_state: "awaiting_payment",
        }),
      }
    );

    if (!transitionResponse.ok) {
      const error = await transitionResponse.json();
      console.error("Transition rejected:", error);
    } else {
      const result = await transitionResponse.json();
      console.log("New session state:", result.state);
    }
    ```

    After a successful transition, ProcureNet emits a transition event on your stream connection. Your stream handler receives the new state so your UI can update without polling.

    <Tip>
      For high-value transactions, call `POST /api/v7/sessions/{id}/escrow-accept` before the final transition to satisfy ProcureNet's legal compliance requirement. The escrow endpoint writes an immutable audit trail entry that unlocks the payment transition.
    </Tip>
  </Step>

</Steps>

## Deprecated Endpoint Notice

<Warning>
  **`POST /api/payments/route` is deprecated** and will be removed in a future release. Migrate to the v7 pipeline:

  1. Call `POST /api/v7/orchestrate` to start a WCS-scored session.
  2. Call `POST /api/v7/sessions/{id}/funding-method` to set the payment method on the session.

  The old `/api/payments/route` endpoint does not support WCS scoring, transport selection, or the v7 state machine. Any new integration should use the v7 endpoints exclusively.
</Warning>
