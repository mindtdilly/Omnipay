ProcureNet uses a local-first vector store to power AI-driven lookups for buyer profiles, contract rules, translations, and entitlements. The store runs on-device alongside the OpenClaw agent swarm, meaning reads are low-latency and survive network interruptions. You do not write vectors yourself — the platform populates and queries the store automatically based on the data you supply to the orchestration API.

## The Four Indexes

The vector store contains four named indexes. Each serves a distinct role in the orchestration pipeline.

<CardGroup cols={2}>
  <Card title="wcs_profiles" icon="user">
    **Type: `scoring`**

    Stores embedding representations of buyer identity signals. Powers the Wallet Confidence Score engine to resolve sessions as `resolved`, `partial`, or `anonymous`.
  </Card>
  <Card title="contract_rules" icon="file-contract">
    **Type: `validation`**

    Holds procurement contract terms and validation logic. Checked during state transitions to ensure orders comply with applicable rules before advancing.
  </Card>
  <Card title="translations" icon="language">
    **Type: `i18n`**

    Contains localized string embeddings for checkout UI flows. Enables ProcureNet to serve the correct language and locale to buyers without round-trips to a remote translation service.
  </Card>
  <Card title="entitlements" icon="badge-check">
    **Type: `authorization`**

    Controls which features and funding methods a buyer or account can access. Queried when you call the funding-method endpoint to verify the buyer is permitted to use the selected payment method.
  </Card>
</CardGroup>

## Vector Item Structure

Every item stored in any index shares the same shape, defined in ProcureNet's internal schema.

<ResponseField name="id" type="string" required>
  A unique identifier for this vector item within its index.
</ResponseField>

<ResponseField name="vector" type="number[]" required>
  The embedding float array produced by the index's configured embedding model.
  Array length matches the `dimensions` value declared for that index.
</ResponseField>

<ResponseField name="payload" type="object" required>
  Arbitrary metadata attached to the vector item. Shape varies by index type —
  for example, `wcs_profiles` payloads contain buyer signal fields, while
  `contract_rules` payloads contain rule predicates.
</ResponseField>

<ResponseField name="updatedAt" type="string (ISO 8601)" required>
  Timestamp of the last write to this item. Used by the OpenClaw reliability
  worker to detect stale entries and trigger re-embedding.
</ResponseField>

<ResponseField name="ttlSeconds" type="integer">
  Optional expiry in seconds from `updatedAt`. When set, the item is
  automatically evicted from the index once the TTL elapses. Commonly applied
  to `wcs_profiles` items for short-lived anonymous sessions.
</ResponseField>

## How Each Index Affects Your Integration

The indexes work together as a pipeline. Understanding their roles helps you pass the right data at the right time.

<Steps>
  <Step title="Buyer signals flow into wcs_profiles">
    When you call `POST /api/v7/orchestrate`, ProcureNet embeds the identity
    signals you supply in the `hints` object — `customerId`, `email`, `phone`,
    and `deviceId` — and queries the `wcs_profiles` index to calculate the
    Wallet Confidence Score. A richer profile means a higher score and a
    `resolved` session mode.
  </Step>
  <Step title="contract_rules validates state transitions">
    Before the state machine advances on `POST /api/v7/sessions/{id}/transition`,
    applicable rules from `contract_rules` are retrieved and evaluated. If your
    order violates a procurement rule, the transition is rejected with a
    validation error.
  </Step>
  <Step title="translations localise the checkout flow">
    ProcureNet resolves the buyer's locale from session context and queries the
    `translations` index to return correctly localised strings. No action is
    required from you — locale handling is automatic.
  </Step>
  <Step title="entitlements gate funding methods">
    When you call `POST /api/v7/sessions/{id}/funding-method`, ProcureNet
    queries the `entitlements` index against the buyer's session to confirm
    the requested payment method is permitted. Requests for unauthorised
    methods are rejected with a `403` response.
  </Step>
</Steps>

## Schema Reference (Condensed)

The full index schema follows JSON Schema draft 2020-12. The abbreviated structure below shows the shape of each index object.

```json JSON
{
  "indexes": {
    "<index_name>": {
      "name": "string",
      "type": "i18n | validation | scoring | authorization",
      "embeddingModel": "string",
      "dimensions": 1536,
      "items": [
        {
          "id": "string",
          "vector": [0.021, -0.113, "..."],
          "payload": {},
          "updatedAt": "2025-01-15T10:30:00Z",
          "ttlSeconds": 3600
        }
      ]
    }
  }
}
```

<Note>
  The vector store is managed internally by OpenClaw agents — you do not write vectors directly. Buyer data you pass to `POST /api/v7/orchestrate` is used to populate and query profiles automatically.
</Note>

<Tip>
  If buyer lookups are returning `anonymous` mode unexpectedly, ensure you are passing all four identity signals — `customerId`, `email`, `phone`, and `deviceId` — in the `hints` object of your orchestration request. Missing signals reduce the Wallet Confidence Score and may drop the session below the `resolved` threshold of 100 points.
</Tip>
